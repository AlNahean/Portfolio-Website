**Naive RAG** (Basic RAG) is the architectural baseline for grounding Large Language Models in private data. It operates as a linear "Retrieve-then-Generate" bridge. The system identifies relevant document snippets from a local depository and injects them into the model context window before inference. This creates a factual anchor, mitigating the risk of hallucinations and providing clear data provenance.

### Engineering Trade-offs

| Feature | Technical Impact |
| :--- | :--- |
| **Pros** | Low architectural complexity; stateless execution; minimal latency overhead for small datasets. |
| **Cons** | Linear memory scaling limits; sensitive to chunk boundaries; lacks support for multi-document relational reasoning. |

## Architecture Overview

The transformation from binary document data to a grounded response follows this data flow:

```text
        [Document]
             │
             ▼
   ┌───────────────────┐
   │  unpdf Extraction  │
   └─────────┬─────────┘
             │
     ┌───────┴───────┐
     ▼               ▼
 ┌───────────┐   ┌───────────┐
 │ Chunk A   │   │ Chunk B   │ (Recursive Character Splitting)
 │ (Size: X) │   │ (Size: X) │
 └─────┬─────┘   └─────┬─────┘
       └───────┬───────┘
               ▼
     ┌───────────────────┐
     │  Vercel AI SDK    │
     │  (Vectorization)  │
     └─────────┬─────────┘
               ▼
     ┌───────────────────┐
     │ Context Injection │ (Balancing Precision vs Context)
     └───────────────────┘
```

This script consolidates the logic into a single execution unit with verbose logging.

<TabsContent value="script">
```javascript
import fs from 'fs/promises';
import { getDocumentProxy, extractText } from 'unpdf';
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";
import { embedMany, embed, cosineSimilarity, generateText } from 'ai';
import { openai } from '@ai-sdk/openai';
import 'dotenv/config';

/**
 * Senior Developer RAG Baseline
 * Optimized for local search and document-specific grounding.
 */
async function main() {
  const logger = {
    info: (msg) => console.log(`[INFO]  ${new Date().toISOString()} | ${msg}`),
    timer: (label) => console.time(`[TIME]  ${label}`),
    timerEnd: (label) => console.timeEnd(`[TIME]  ${label}`)
  };

  try {
    logger.info("Initializing RAG Pipeline execution...");
    
    // 1. Ingestion
    logger.timer("extraction");
    const buffer = await fs.readFile('./data/AI_Information.pdf');
    const pdfProxy = await getDocumentProxy(new Uint8Array(buffer));
    const { text: rawText } = await extractText(pdfProxy, { mergePages: true });
    logger.timerEnd("extraction");
    logger.info(`Source text extracted: ${rawText.length} characters.`);

    // 2. Recursive Chunking
    const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 1000, chunkOverlap: 200 });
    const segments = await splitter.splitText(rawText);
    logger.info(`Logical segments created: ${segments.length}`);

    // 3. Vectorization
    logger.timer("indexing");
    const { embeddings } = await embedMany({
      model: openai.embedding('text-embedding-3-small'),
      values: segments,
    });
    const vectorStore = segments.map((text, i) => ({ text, vector: embeddings[i] }));
    logger.timerEnd("indexing");
    logger.info(`Vector store populated in memory.`);

    // 4. Inference and Grounding
    const userQuery = "What specific risks does the document outline regarding AI alignment?";
    logger.info(`Query submitted: "${userQuery}"`);

    const { embedding: queryVector } = await embed({
      model: openai.embedding('text-embedding-3-small'),
      value: userQuery,
    });

    const context = vectorStore
      .map(item => ({ text: item.text, score: cosineSimilarity(queryVector, item.vector) }))
      .sort((a, b) => b.score - a.score)
      .slice(0, 3)
      .map(m => m.text)
      .join("\n\n---\n\n");

    logger.timer("llm-generation");
    const { text } = await generateText({
      model: openai('gpt-4o-mini'),
      system: "You are a research analyst. Use provided context to answer questions precisely.",
      prompt: `Context:\n${context}\n\nQuestion: ${userQuery}`,
    });
    logger.timerEnd("llm-generation");

    console.log(`\n--- AI GROUNDED RESPONSE ---\n${text}\n---------------------------\n`);

  } catch (error) {
    console.error(`[FATAL] Pipeline failed: ${error.message}`);
  }
}

main();
```

## Summary of Impact

| Metric | Standard LLM | Basic RAG Pipeline |
| :--- | :--- | :--- |
| **Data Scope** | Static Training Data | Live Document Context |
| **Hallucination Risk** | Significant on Niche Topics | Traceable and Low |
| **Provenance** | None | Directly Citable |
| **System Latency** | Baseline | Baseline + ~3s (Search & Vectorization) |

## When to Use This
- Small internal technical knowledge bases.
- Validating retrieval logic before scaling to a production vector database.
- Applications where data must remain local and transient (in-memory).
