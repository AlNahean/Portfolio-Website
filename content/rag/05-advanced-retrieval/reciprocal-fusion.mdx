**Hybrid Search** with **Reciprocal Rank Fusion** (RRF) is the gold standard for production-grade retrieval. Keyword search (BM25) is excellent for finding specific proper nouns and identifiers (e.g., "Error Code 404"), while vector search is excellent for finding conceptual similarities (e.g., "How to fix node issues"). RRF allows us to merge these two distinct rankings into a single, unified list without requiring manual weight tuning.

### Engineering Trade-offs

| Feature | Technical Impact |
| :--- | :--- |
| **Pros** | Maximizes recall across name-heavy and concept-heavy queries; provides a unified score for disparate systems. |
| **Cons** | Requires maintaining two indices (BM25 + Vector); increases the total search execution time. |

## Architecture Overview

The Hybrid RRF data flow unifies disparate search systems:

```text
       [USER Query]
             │
     ┌───────┴───────┐
     ▼               ▼
┌───────────┐   ┌───────────┐
│ Keyword   │   │ Semantic  │ (BM25 + Vector Search)
│ (BM25)    │   │ (Vector)  │
└─────┬─────┘   └─────┬─────┘
      │               │
      └───────┬───────┘
              ▼
    ┌───────────────────┐
    │ RRF Scoring Logic │ (Consolidate Rankings)
    └─────────┬─────────┘
              ▼
    ┌───────────────────┐
    │ Unified Context   │ (High-precision candidates)
    └───────────────────┘
```

<Step title="RRF Score Consolidation">
We apply the RRF formula: **Score = Σ (1 / (rank + k))**. This rewards documents that appear high in *multiple* rankings.

/**
 * RRF Score Function

  return 1 / (60 + rank);

```javascript
import 'dotenv/config';

/**
 * Advanced Reciprocal Rank Fusion (RRF) Pipeline.
 */
async function fusionSearch() {
  const logger = {
    info: (msg) => console.log(`[INFO]  ${new Date().toISOString()} | ${msg}`),
  };

  try {
    // 1. Independent results pool (Simulated)
    const setA = ["docX", "docY", "docZ"]; // Rank 0, 1, 2
    const setB = ["docA", "docX", "docB"]; // Rank 0, 1, 2

    logger.info("Fusing keyword and semantic ranking sets...");

    // 2. Compute Unified RRF
    const k = 60;
    const scores = {};

    [setA, setB].forEach((set) => {
      set.forEach((doc, rank) => {
        scores[doc] = (scores[doc] || 0) + (1 / (k + rank));
      });
    });

    const finalRanking = Object.entries(scores)
                               .sort((a, b) => b[1] - a[1]);

    logger.info(`Top fused match: "${finalRanking[0][0]}" with RRF score: ${finalRanking[0][1].toFixed(6)}`);
    console.log(`\n--- FUSION SUCCESS: HYBRID RETRIEVAL ACTIVE ---\n`);

  } catch (error) {
    console.error(`[FATAL] Fusion failed: ${error.message}`);
  }
}

fusionSearch();
```

## Summary of Impact

| Metric | Vector Only | Keyword Only | Hybrid (RRF) |
| :--- | :--- | :--- | :--- |
| **Proper Noun Accuracy** | Low | High | Very High |
| **Conceptual Coverage** | High | Low | Very High |
| **Tuning Overhead** | None | None | None |

## When to Use This
- For production RAG systems where both technical terminology and broad logic are queried.
- To improve robustness without manually weighting search importance.
- When your vector store matches conceptually similar but factually wrong chunks due to a lack of keyword weight.
