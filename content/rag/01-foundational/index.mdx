Retrieval-Augmented Generation (RAG) is not a single tool, but a modular architectural pattern designed to connect Large Language Models to live, private, or specialized data. By separating the model's reasoning capabilities from its knowledge base, RAG allows engineers to build AI systems that are verifiable, updateable, and secure.

This overview breaks down the four core components used throughout this curriculum: Extraction, Chunking, Retrieval, and Generation.

## The Modular RAG Pipeline

The system operates as a data bridge, moving information through four distinct states:

### 1. The Ingestion Layer (Indexing)
Raw data is transformed into a searchable format. This involves extracting text from complex formats like PDFs via `unpdf` and calculating high-dimensional embeddings that represent semantic meaning.

### 2. The Retrieval Layer (Discovery)
When a query enters the system, the pipeline must identify which specific snippets of data are relevant. This is typically done via vector similarity or hybrid search (combining keywords and meaning).

### 3. The Augmentation Layer (Contextualization)
The retrieved data is "stuffed" into the LLM's prompt. This turns a general-purpose model into a specialized assistant that has the "open book" required to answer correctly.

### 4. The Generation Layer (Inference)
The reasoning model (e.g., `gpt-5.4-nano`) processes the context and query to produce a grounded response.

<Callout>
**The Legal Researcher Analogy**
Think of the LLM as a **Senior Attorney** with high reasoning skills but no knowledge of your specific case. **Indexing** is the filing cabinet. **Retrieval** is the paralegal who finds the three relevant folders. **Augmentation** is placing those folders on the attorney's desk. **Generation** is the attorney writing the brief based on those specific documents.
</Callout>

## Final Baseline Script (minimal-rag.js)

This script provides a functional verification that your environment is ready for more advanced RAG patterns.

```javascript
import fs from 'fs/promises';
import { getDocumentProxy, extractText } from 'unpdf';
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";
import { embedMany, embed, cosineSimilarity, generateText } from 'ai';
import { openai } from '@ai-sdk/openai';
import 'dotenv/config';

const Log = {
  step: (s) => console.log(`\n--- ${s.toUpperCase()} ---`),
  info: (m) => console.log(`[INFO] ${m}`),
  success: (m) => console.log(`[OK]   ${m}`),
};

async function testRAGBaseline() {
  Log.step("Environment Check");
  
  // 1. Minimal Extraction
  const buffer = await fs.readFile('./data/AI_Information.pdf');
  const proxy = await getDocumentProxy(new Uint8Array(buffer));
  const { text: fullText } = await extractText(proxy, { mergePages: true });
  Log.info("PDF access confirmed.");

  // 2. Minimal Chunking
  const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 500, chunkOverlap: 50 });
  const chunks = await splitter.splitText(fullText.slice(0, 2000));
  Log.info("Chunking logic ready.");

  // 3. Minimal Indexing
  const { embeddings } = await embedMany({
    model: openai.embedding('text-embedding-3-small'),
    values: chunks,
  });
  Log.success("Vectorization engine ready.");

  console.log("\nBaseline verification complete. You are ready for advanced techniques.");
}

testRAGBaseline().catch(console.error);
```
