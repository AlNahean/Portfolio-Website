**Basic RAG** (Naive RAG) is the foundational architecture for building production-grade AI. By allowing the AI to consult private documents in real-time, it effectively eliminates the limitations of static training data and reduces hallucinations.

This implementation follows a **Senior Developer's workflow**: utilizing `unpdf` for robust, platform-agnostic extraction, LangChain for semantic chunking, and the Vercel AI SDK v6 for high-speed vectorized search and inference.

## How the Pipeline Works

The system operates as a linear data bridge between static files and a reasoning model:

### 1. The Extraction and Chunking Phase
Raw binary PDF data is parsed into a clean string using `unpdf`. To ensure the LLM can process the data without losing meaning, LangChain’s `RecursiveCharacterTextSplitter` breaks the text into 1,000-character chunks with a 200-character contextual overlap.

### 2. The Indexing Phase
These text chunks are converted into high-dimensional vectors using OpenAI's `text-embedding-3-small`. These numerical representations of meaning are stored in a simple JavaScript array for rapid comparison.

### 3. The Retrieval Phase
When a user asks a question, the query is vectorized. The system then uses **Cosine Similarity** to mathematically find the snippets in memory that most closely match the user's intent.

### 4. The Generation Phase
Retrieved snippets are injected into the model instructions. Using the AI SDK's `generateText`, the model is instructed: "Based only on the context provided below, answer the question."

<Callout>
**The Open-Book Analogy**
A standard LLM query is like asking a student to take a test from memory. **Basic RAG** is an **open-book exam**: the model is provided with the exact pages of the textbook needed to answer the question, ensuring it cites facts rather than guessing.
</Callout>

```javascript
import fs from 'fs/promises';
import { getDocumentProxy, extractText } from 'unpdf';
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";
import { embedMany, embed, cosineSimilarity, generateText } from 'ai';
import { openai } from '@ai-sdk/openai';
import 'dotenv/config';

const CONFIG = {
  pdfPath: './data/AI_Information.pdf',
  chunkSize: 1000,
  chunkOverlap: 200,
  embeddingModel: 'text-embedding-3-small',
  generationModel: 'gpt-5.4-nano',
};

const Log = {
  info: (msg) => console.log(`[INFO]  ${new Date().toLocaleTimeString()} | ${msg}`),
  success: (msg) => console.log(`[OK]    ${new Date().toLocaleTimeString()} | ${msg}`),
  step: (step) => console.log(`\n--- STEP: ${step.toUpperCase()} ---`),
};

async function runPipeline() {
  try {
    Log.step("Extraction");
    const dataBuffer = await fs.readFile(CONFIG.pdfPath);
    const pdfProxy = await getDocumentProxy(new Uint8Array(dataBuffer));
    const { text: fullText } = await extractText(pdfProxy, { mergePages: true });
    
    const splitter = new RecursiveCharacterTextSplitter({
      chunkSize: CONFIG.chunkSize,
      chunkOverlap: CONFIG.chunkOverlap,
    });
    const chunks = await splitter.splitText(fullText);
    Log.success(`Extracted and split into ${chunks.length} chunks.`);

    Log.step("Indexing");
    const { embeddings } = await embedMany({
      model: openai.embedding(CONFIG.embeddingModel),
      values: chunks,
    });
    const vectorStore = chunks.map((text, i) => ({ text, embedding: embeddings[i] }));
    Log.success("Vector store initialized.");

    Log.step("Inference");
    const query = "What is the primary risk profile of this technology?";
    const { embedding: queryEmbedding } = await embed({
      model: openai.embedding(CONFIG.embeddingModel),
      value: query,
    });

    const context = vectorStore
      .map(item => ({ text: item.text, similarity: cosineSimilarity(queryEmbedding, item.embedding) }))
      .sort((a, b) => b.similarity - a.similarity)
      .slice(0, 3)
      .map(m => m.text).join("\n\n---\n\n");

    const { text } = await generateText({
      model: openai(CONFIG.generationModel),
      system: "You are a research assistant. Answer using ONLY the provided context.",
      prompt: `Context:\n${context}\n\nQuestion: ${query}`,
    });

    console.log(`\nAI Response:\n${text}`);

  } catch (err) {
    console.error("Critical failure:", err);
  }
}

runPipeline();
```

## Summary of Impact

| Metric | Standard LLM | Basic RAG |
| :--- | :--- | :--- |
| **Factual Accuracy** | Outdated / General | Document-Specific (Citable) |
| **Hallucination Risk** | High | Very Low |
| **Data Privacy** | No Control | High (Localized Context) |
| **Latency** | Low (Single Call) | Medium (Search + Inference) |

## Best Practices and Use Cases
- **Technical Support**: Ground bots in specific API documentation versions to avoid outdated advice.
- **Legal and Compliance**: Perform Q&A over internal contracts and PDFs without expensive fine-tuning.
- **Rapid Prototyping**: Test RAG logic and prompt strategies before committing to a managed database like Pinecone or Postgres.
