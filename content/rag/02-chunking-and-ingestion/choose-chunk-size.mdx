Choosing the correct chunk size is one of the most impactful hyperparameter decisions in a RAG pipeline. The goal is to isolate the specific information required to answer a query without losing the surrounding context that gives that information meaning.

This guide demonstrates how to programmatically test and evaluate different chunking configurations using LangChain's recursive splitters and Vercel AI SDK v6.

## The Granularity Trade-off

Retrieval performance is governed by two competing forces:

1.  **Precision (Small Chunks)**: Splitting text into tiny segments (e.g., 100-300 characters) ensures the vector search finds very specific facts. However, the LLM may lack the context needed to understand those facts.
2.  **Recall/Context (Large Chunks)**: Large segments (e.g., 2000+ characters) ensure the LLM sees the "big picture." However, specific answers can be "lost in the noise," reducing the mathematical similarity of the chunk to the user's query.

<Callout>
**The Microscope Analogy**
Think of chunk size as the **zoom level of a microscope**. If you zoom in too far (Small Chunk), you see individual cells but lose track of which organ you are looking at. If you zoom out too far (Large Chunk), you see the whole organism but cannot identify the specific cellular defect.
</Callout>

```javascript
import fs from 'fs/promises';
import { getDocumentProxy, extractText } from 'unpdf';
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";
import { embedMany, embed, cosineSimilarity, generateText } from 'ai';
import { openai } from '@ai-sdk/openai';
import 'dotenv/config';

const CONFIG = {
  pdfPath: './data/AI_Information.pdf',
  chunkSize: 800,
  chunkOverlap: 150,
  embeddingModel: 'text-embedding-3-small',
  generationModel: 'gpt-5.4-nano',
};

const Log = {
  info: (msg) => console.log(`[INFO]  ${new Date().toLocaleTimeString()} | ${msg}`),
  success: (msg) => console.log(`[OK]    ${new Date().toLocaleTimeString()} | ${msg}`),
  step: (step) => console.log(`\n--- STEP: ${step.toUpperCase()} ---`),
};

async function runPipeline() {
  try {
    Log.step("Data Preparation");
    const dataBuffer = await fs.readFile(CONFIG.pdfPath);
    const pdfProxy = await getDocumentProxy(new Uint8Array(dataBuffer));
    const { text: fullText } = await extractText(pdfProxy, { mergePages: true });
    
    const splitter = new RecursiveCharacterTextSplitter({
      chunkSize: CONFIG.chunkSize,
      chunkOverlap: CONFIG.chunkOverlap,
    });
    const chunks = await splitter.splitText(fullText);
    Log.info(`Processed ${chunks.length} chunks.`);

    Log.step("Indexing");
    const { embeddings } = await embedMany({
      model: openai.embedding(CONFIG.embeddingModel),
      values: chunks,
    });
    const vectorStore = chunks.map((text, i) => ({ text, embedding: embeddings[i] }));
    Log.success("Vectorization complete.");

    Log.step("Retrieval");
    const query = "What is the specific methodology for safety alignment?";
    const { embedding: queryEmbedding } = await embed({
      model: openai.embedding(CONFIG.embeddingModel),
      value: query,
    });

    const context = vectorStore
      .map(item => ({ text: item.text, similarity: cosineSimilarity(queryEmbedding, item.embedding) }))
      .sort((a, b) => b.similarity - a.similarity)
      .slice(0, 3)
      .map(m => m.text).join("\n\n---\n\n");

    const { text } = await generateText({
      model: openai(CONFIG.generationModel),
      system: "Answer using provided context fragments. If similarity is low, state you lack information.",
      prompt: `Context:\n${context}\n\nQuestion: ${query}`,
    });

    console.log(`\nResponse:\n${text}`);

  } catch (err) {
    console.error("Pipeline failure:", err);
  }
}

runPipeline();
```

## Summary of Impact

| Metric | Small Chunks (200) | Medium Chunks (800) | Large Chunks (2000) |
| :--- | :--- | :--- | :--- |
| **Retrieval Precision** | High | Balanced | Low |
| **Contextual Meaning** | Poor | Good | Excellent |
| **Token Usage** | Low | Medium | High |
| **Latency** | Low | Low | Medium |

## Scaling to Production
- **Use Local Search First**: For fewer than 1,000 chunks, a JavaScript array with `cosineSimilarity` is faster and cheaper than an external database.
- **Implement Source References**: As your chunk size decreases, it becomes more critical to pass the original filename and page number in the metadata to allow the LLM to provide verifiable citations.
- **Dynamic Sizing**: For mixed document types (e.g., source code vs. prose), consider using different splitters for different file extensions.
