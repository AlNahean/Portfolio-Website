**Propositions Chunking** is an advanced ingestion strategy that moves away from segments of text toward "atomic facts." Instead of storing a paragraph that contains multiple ideas, an LLM is used during the indexing phase to rewrite the text into a series of standalone sentences—propositions—where each sentence contains exactly one independent thought.

This approach significantly improves retrieval accuracy for specific questions because every vector in your database represents a pure, unclouded fact, removing the "distraction" of surrounding sentences.

## How the Pipeline Works

This strategy utilizes the LLM as a data architect before the embedding process begins:

1.  **Deconstruction**: The document is passed to a high-reasoning model (like `gpt-5.4-nano`).
2.  **Fact Extraction**: The model rewrites the text into a JSON array of "propositions." Each proposition must be a complete sentence that can be understood without referring to the previous one.
3.  **Context Injection**: If a sentence uses a pronoun (e.g., "It was founded in 1990"), the LLM replaces it with the actual subject ("The company was founded in 1990").
4.  **Atomic Indexing**: Each individual proposition is embedded and stored as a unique entry in the memory store.

<Callout>
**The Lego Analogy**
Standard chunking is like storing **pre-built sections** of a Lego set. If you need a specific 2x4 red brick, you have to dig through a pre-built house to find it. **Propositions Chunking** is like taking the house apart and storing every **individual brick** separately. Finding exactly what you need is instantaneous and precise.
</Callout>

```javascript
import fs from 'fs/promises';
import { getDocumentProxy, extractText } from 'unpdf';
import { generateObject, embedMany, embed, cosineSimilarity, generateText } from 'ai';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';
import 'dotenv/config';

const CONFIG = {
  pdfPath: './data/AI_Information.pdf',
  embeddingModel: 'text-embedding-3-small',
  generationModel: 'gpt-5.4-nano',
};

const Log = {
  info: (msg) => console.log(`[INFO]  ${msg}`),
  step: (step) => console.log(`\n--- ${step.toUpperCase()} ---`),
  success: (msg) => console.log(`[OK]    ${msg}`),
};

async function runPropositionsPipeline() {
  try {
    Log.step("Extraction");
    const dataBuffer = await fs.readFile(CONFIG.pdfPath);
    const pdfProxy = await getDocumentProxy(new Uint8Array(dataBuffer));
    const { text: fullText } = await extractText(pdfProxy, { mergePages: true });

    Log.step("Proposition Generation");
    // Breaking text into large segments first to keep LLM costs sane
    const segments = fullText.match(/.{1,2000}/g) || [fullText];
    const allPropositions = [];

    for (const segment of segments) {
      const { object } = await generateObject({
        model: openai(CONFIG.generationModel),
        schema: z.object({
          propositions: z.array(z.string())
        }),
        system: "Rewrite the segment into a list of atomic, standalone factual sentences.",
        prompt: segment
      });
      allPropositions.push(...object.propositions);
    }
    Log.info(`Generated ${allPropositions.length} atomic propositions.`);

    Log.step("Indexing");
    const { embeddings } = await embedMany({
      model: openai.embedding(CONFIG.embeddingModel),
      values: allPropositions,
    });
    const vectorStore = allPropositions.map((text, i) => ({ text, embedding: embeddings[i] }));

    Log.step("High Precision Retrieval");
    const query = "When was the safety framework established?";
    const { embedding: queryVector } = await embed({
      model: openai.embedding(CONFIG.embeddingModel),
      value: query,
    });

    const context = vectorStore
      .map(item => ({ text: item.text, similarity: cosineSimilarity(queryVector, item.embedding) }))
      .sort((a, b) => b.similarity - a.similarity)
      .slice(0, 5) // Use more snippets since they are atomic
      .map(m => m.text).join(" ");

    const { text } = await generateText({
      model: openai(CONFIG.generationModel),
      system: "Answer based only on these atomic facts.",
      prompt: `Context: ${context}\n\nQuestion: ${query}`
    });

    console.log(`\nAI Answer: ${text}`);

  } catch (err) {
    console.error(err);
  }
}

runPropositionsPipeline();
```

## Summary of Impact

| Metric | Standard Chunking | Propositions Chunking |
| :--- | :--- | :--- |
| **Retrieval Resolution** | Paragraph level | **Statement level** |
| **Hallucination Risk** | Low | **Near-Zero** |
| **Noise Reduction** | Moderate | **Maximum** |
| **Ingestion Cost** | Low | High (Requires LLM processing) |

## When to Use This
- **Fact-Checking Systems**: Where missing one small detail leads to a false conclusion.
- **Legal/Medical Q&A**: Where precise extraction of dates, names, and dosages is mandatory.
- **Small, High-Value Datasets**: Where the cost of processing is negligible compared to the cost of an incorrect answer.
- **Improving Retrieval for Short Queries**: Standalone facts are more likely to match short user queries than long, noisy paragraphs.
